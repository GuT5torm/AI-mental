================================================================
ai-vue 项目语法详细讲解（含示例）
================================================================
说明：本文件讲解 C:\WWORKSPA\code\ai-vue 这个 Vue 3 项目中用到的
主要语法、它们的作用，以及数据从何处来。示例均取自本项目真实代码。

项目定位：一个心理健康 / AI 助手管理后台，前端用 Vue 3 + Vite +
Element Plus + Pinia + Axios，后端为远程服务（159.75.169.224:1235）。

----------------------------------------------------------------
一、项目整体结构与入口
----------------------------------------------------------------
目录概览：
  index.html              HTML 入口
  vite.config.js          Vite 构建与开发代理配置
  package.json            依赖与脚本声明
  src/
    main.js               应用启动与全局挂载
    App.vue               根组件（只放 <router-view>）
    router/index.js       前端路由
    config/index.js       全局常量（文件基地址）
    utils/request.js      Axios 实例 + 拦截器（数据请求核心）
    api/gutts.js          按业务封装的接口函数
    stores/gutts.js       Pinia 状态（侧边栏折叠）
    components/           复用组件（布局、搜索、弹窗、富文本等）
    views/                页面级组件（登录、知识文章、咨询等）

index.html 关键一行：
  <script type="module" src="/src/main.js"></script>
  <div id="app"></div>
作用：浏览器加载 main.js（type="module" 表示用 ES Module），
最终 Vue 会把整个应用渲染进 id="app" 的 div。

App.vue 关键一行：
  <template><router-view></router-view></template>
作用：<router-view> 是"路由出口"，当前 URL 匹配到的页面组件会
渲染到这里。几乎所有页面都通过它显示。

二、ES Module（import / export）
----------------------------------------------------------------
语法：使用 import 引入、export 导出，而不是旧的 require()。
来源：package.json 中有 "type": "module"，整项目启用 ES Module。

示例（main.js）：
  import { createApp } from 'vue'
  import ElementPlus from 'element-plus'
  import router from './router'
  export default router          // router/index.js 末尾导出路由实例
作用：把分散的模块（vue 库、UI 库、自己写的路由）组合到 main.js。

命名导出示例（api/gutts.js）：
  export function login(data){ return service.post('/user/login', data) }
  export function articlePage(params){ ... }
使用端：
  import { login, articlePage } from '@/api/gutts'
作用：一个文件可导出多个函数；使用端按需 import，打包时利于摇树优化。

----------------------------------------------------------------
三、main.js —— 全局注册与插件挂载
----------------------------------------------------------------
  const app = createApp(App)
  const pinia = createPinia()
  for (const [key, component] of Object.entries(ElementPlusIconsVue)) {
    app.component(key, component)   // 全局注册每一个图标组件
  }
  app.use(ElementPlus).use(router).use(pinia).mount('#app')

语法点：
1) createApp(App)：以根组件创建应用实例。
2) app.component(name, comp)：全局注册组件，注册后任意 .vue 模板
   都能直接用 <组件名>，无需再 import。这里把全部图标注册成全局，
   所以模板里能直接写 <PieChart/>、<Back/>、<Expand/> 等。
3) app.use(plugin)：安装插件。ElementPlus（UI 库）、router（路由）、
   pinia（状态管理）都需 use 一次才生效。
4) .mount('#app')：把应用挂到 index.html 的 #app 节点，页面才出现。

四、vite.config.js —— 路径别名与开发代理
----------------------------------------------------------------
  import { resolve } from 'path'
  export default defineConfig({
    plugins: [vue()],
    resolve: { alias: { '@': resolve(import.meta.dirname, 'src') } },
    server: {
      proxy: {
        '/api': { target: 'http://159.75.169.224:1235', changeOrigin: true }
      }
    }
  })

语法点：
1) resolve.alias：把 '@' 映射到 src 目录。于是
   import X from '@/api/gutts' 等价于 import X from 'src/api/gutts'，
   再也不用手写 '../../'。
2) server.proxy：开发服务器代理。前端请求 '/api/xxx' 时，Vite 会
   把它转发到 target 指向的真实后端，并自动处理跨域。
   => 这就是为什么代码里地址都写 '/api/...' 而不是完整域名。

----------------------------------------------------------------
五、单文件组件 SFC（.vue 三段式）
----------------------------------------------------------------
每个 .vue 文件由三部分组成：
  <template>   视图结构（HTML + Vue 指令）
  <script setup> 逻辑（JS，组合式 API）
  <style scoped lang="scss"> 样式（scoped=只作用于本组件）

示例（login.vue 头部）：
  <template>
    <el-form ref="ruleFormRef" :model="formData" :rules="rules">
      <el-form-item label="用户名或邮箱" prop="username">
        <el-input v-model="formData.username" placeholder="请输入用户名" />
      </el-form-item>
    </el-form>
  </template>
  <script setup>
  import { ref, reactive } from 'vue'
  const formData = reactive({ username: '', password: '' })
  </script>
  <style scoped lang="scss">
  .container { width: 384px; }
  </style>

语法点：
- lang="scss"：启用 SCSS 嵌套写法（如 .container { .title { ... } }）。
- scoped：样式只对本组件生效，不会污染其它组件（Vite 会给 class
  加属性选择器实现隔离）。

----------------------------------------------------------------
六、<script setup> 与组合式 API
----------------------------------------------------------------
<script setup> 是 Vue 3 推荐的写法：在顶层声明的变量/函数自动暴露给
模板，不必写 export default。

示例（knowledge.vue）：
  <script setup>
  import { onMounted, ref, reactive } from 'vue'
  const tableData = ref([])
  const pagination = reactive({ currentPage: 1, pageSize: 10, total: 0 })
  onMounted(async () => { /* 组件挂载后请求数据 */ })
  </script>

语法点：
- onMounted：生命周期钩子，组件渲染到页面后自动执行（常用于拉取首屏数据）。
- 顶层声明即公开：tableData、pagination 在模板里可直接用。

----------------------------------------------------------------
七、ref 与 reactive（响应式数据）
----------------------------------------------------------------
Vue 的核心是"响应式"——数据变了，视图自动更新。

1) ref：用于基本类型，或需要整体替换的数组/对象。
   模板中直接用，脚本中要用 .value。
   示例（knowledge.vue）：
     const tableData = ref([])        // 初始空数组
     tableData.value = records        // 请求回来后整体替换，视图自动刷新
   注意：调接口拿到数据后必须写 .value 才生效。

2) reactive：用于对象/表单，属性可直接读写，不需要 .value。
   示例（login.vue）：
     const formData = reactive({ username: '', password: '' })
     const rules = reactive({
       username: [{ required: true, message: '请输入用户名', trigger: 'blur' }]
     })
   修改：formData.username = 'abc'   // 直接赋值即可，视图同步

对比记忆：
   ref(x)      ->  脚本里用 x.value，模板里用 x
   reactive(o) ->  脚本/模板里都用 o.key

----------------------------------------------------------------
八、computed（计算属性，带缓存）
----------------------------------------------------------------
根据已有数据派生出新值，且只在依赖变化时重算。

示例 A（ArticleDialog.vue，实现 v-model 双向绑定）：
  const dialogVisible = computed({
    get() { return props.modelValue },        // 读：取父组件传入的值
    set(val) { emit('update:modelValue', val) } // 写：通知父组件更新
  })
  作用：让子组件能像普通变量一样读写 props.modelValue，父组件用
  <ArticleDialog v-model:modelValue="dialogVisible" /> 即可双向同步。

示例 B（Sidebar.vue，读取全局状态）：
  const isCollapse = computed(() => useGuttsStore().isCollapse)
  作用：侧边栏折叠状态来自 Pinia，用 computed 包装后随状态自动更新。

九、watch（侦听数据变化）
----------------------------------------------------------------
当某个数据变化时执行副作用（如回填表单）。

示例（ArticleDialog.vue）：
  watch(() => props.article, (newVal) => {
    if (newVal) {
      Object.assign(formData, newVal)   // 编辑时把详情填进表单
      businessId.value = newVal.id
      imgUrl.value = fileBaseUrl + newVal.coverImage
    } else {
      formData.title = ''               // 新增时清空
    }
  })
作用：父组件把"当前编辑的文章"传进来，watch 监听到变化后自动
把数据回填到表单，实现"新增/编辑共用一个弹窗"。

----------------------------------------------------------------
十、props 与 emit（父子组件通信）
----------------------------------------------------------------
父传子用 props，子传父用 emit。

1) defineProps（声明接收的属性，可带类型校验）：
   示例（Tablesearch.vue）：
     const props = defineProps({
       formItem: { type: Array, default: () => [] }
     })
   父组件使用：<Tablesearch :formItem="formItem" />

2) defineEmits（声明可触发的事件）：
   示例（Tablesearch.vue）：
     const emit = defineEmits(['search'])
     const handleSearch = () => emit('search', formData)   // 把表单数据抛给父级
   父组件监听：<Tablesearch @search="handleSearch" />

3) v-model 语法糖本质：
   父：<ArticleDialog v-model:modelValue="dialogVisible" />
   子：props.modelValue + emit('update:modelValue', val)
   即 v-model 是 :modelValue + @update:modelValue 的简写。

十一、模板指令（Template Directives）
----------------------------------------------------------------
1) v-model：表单双向绑定
   示例：<el-input v-model="formData.username" />
   用户输入即写入 formData.username，反之亦然。

2) v-if / v-show：条件渲染
   示例（knowledge.vue）：
     <el-button v-if="scope.row.status === 0 || scope.row.status === 2"
                type="success">发布</el-button>
     <el-button v-if="scope.row.status === 1" type="warning">下线</el-button>
   作用：按文章状态（0草稿/1已发布/2已下线）显示不同操作按钮。
   区别：v-if 真正增删 DOM；v-show 只是切 display。

3) v-for：列表渲染
   示例（Sidebar.vue）：
     <el-menu-item v-for="item in router.options.routes[0].children"
                   :key="item.path" :index="item.path">
   作用：遍历路由配置自动生成侧边菜单项。:key 是每个项的唯一标识，
   用于 Vue 高效更新列表（必填）。

4) :prop 与 @event：属性与事件绑定
   ":" 是 v-bind 缩写，绑定动态属性；"@" 是 v-on 缩写，绑定事件。
   示例：<el-table :data="tableData" @change="handleChange" />
   等价于 <el-table v-bind:data="tableData" v-on:change="handleChange" />

5) 作用域插槽（#default="scope"）：
   示例（knowledge.vue）：
     <el-table-column label="分类">
       <template #default="scope">
         <span>{{ categoryMap[scope.row.categoryId] }}</span>
       </template>
     </el-table-column>
   作用：Element Plus 的表格列用插槽把"当前行数据"通过 scope.row
   暴露给你，从而自定义单元格渲染（如把分类 id 映射成名称）。

6) 动态组件 <component :is="...">：
   示例（Tablesearch.vue）：
     <component v-model="formData[item.prop]" :is="isComp(item.comp)" />
   其中 isComp 把 'input'->'elInput'、'select'->'elSelect' 映射。
   作用：根据配置里的类型字段，动态渲染成输入框或下拉框，实现
   "一个搜索组件适配多种字段"。

   示例（Sidebar.vue）：
     <el-icon><component :is="item.meta.icon" /></el-icon>
   作用：按路由 meta.icon 渲染对应图标（如 PieChart、Document）。

十二、vue-router 路由
----------------------------------------------------------------
router/index.js：
  import { createRouter, createWebHistory } from 'vue-router'
  const router = createRouter({
    history: createWebHistory(),   // HTML5 历史模式，URL 无 # 号
    routes: [
      { path: '/back', component: BackendLayout, children: [
          { path: 'dashboard', component: Dashboard, meta: { title: '数据分析', icon: 'PieChart' } },
          { path: 'knowledge', component: Knowledge, meta: { title: '知识文章', icon: 'Document' } }
      ]},
      { path: '/auth', component: AuthLayout, children: [
          { path: 'login', component: () => import('@/views/login.vue') }  // 懒加载
      ]},
      { path: '/', redirect: '/auth/login' }
    ]
  })

语法点：
1) 嵌套路由 children：/back 是布局壳，里面 dashboard/knowledge 等
   作为子路由，渲染进 BackendLayout 里的 <router-view>。
2) meta：自定义路由元信息，这里存标题和图标，供侧边栏读取。
3) () => import('@/views/login.vue')：路由懒加载，访问时才下载该
   页面代码，缩小首屏体积。
4) redirect：访问 '/' 自动跳到 '/auth/login'。
5) 编程式导航：login.vue 中 router.push('/back/dashboard') 跳转到后台。

十三、Pinia 状态管理（stores/gutts.js）
----------------------------------------------------------------
用于跨组件共享状态（比 props 层层传更方便）。

  import { defineStore } from 'pinia'
  import { ref } from 'vue'
  export const useGuttsStore = defineStore('gutts', () => {
    const isCollapse = ref(false)
    const toggleCollapse = () => { isCollapse.value = !isCollapse.value }
    return { isCollapse, toggleCollapse }
  })

使用端（Navbar.vue 折叠按钮）：
  import { useGuttsStore } from '@/stores/gutts.js'
  const handleCollapse = () => useGuttsStore().toggleCollapse()
使用端（Sidebar.vue 菜单宽度）：
  const isCollapse = computed(() => useGuttsStore().isCollapse)
  <el-aside width="isCollapse ? '64px' : '264px'">

作用：Navbar 点一下切换 isCollapse，Sidebar 宽度随之变化。这种
"一个按钮影响另一个组件"的全局状态，正是 Pinia 的用武之地。
注意：Pinia 状态在内存里，刷新页面会重置（没有持久化）。

十四、Axios 封装与拦截器（数据请求核心）
----------------------------------------------------------------
utils/request.js 创建一个统一的请求实例：

  import axios from 'axios'
  const service = axios.create({
    baseURL: '/api',     // 所有请求前缀
    timeout: 5000        // 超时 5 秒
  })

1) 请求拦截器：发送前统一加工
  service.interceptors.request.use((config) => {
    const token = localStorage.getItem('token')
    if (token) config.headers['token'] = token   // 自动带登录凭证
    return config
  })
  作用：每个请求自动在请求头加 token，业务代码不必每次手动写。

2) 响应拦截器：收到后统一解包
  service.interceptors.response.use((response) => {
    const { data, config } = response
    if (data.code === '200') {
      return data.data          // 关键：只把业务数据返回给调用方
    } else if (data.code === '-1') {
      if (!config.url?.includes('login')) {
        ElMessage.error(data.msg || '登录过期，请重新登录')
        localStorage.removeItem('token')
        localStorage.removeItem('userInfo')
        window.location.href = '/auth/login'
      }
    }
    return response
  })

重要结论（为什么要这样写）：
后端返回结构是 { code, msg, data }。拦截器在 code==='200' 时直接
return data.data，所以页面里拿到的就是业务数据本身：
  示例（knowledge.vue）：
    const { records, total } = await articlePage(params)
    tableData.value = records
    pagination.total = total
  —— 你不用自己写 res.data.data，拦截器已经解包了。

api/gutts.js 是对实例的薄封装：
  export function articlePage(params) {
    return service.get('/knowledge/article/page', { params })
  }
  export function uploadFile(file, businessInfo) {
    const formData = new FormData()
    formData.append('file', file)
    formData.append('businessType', 'ARTICLE')
    return service.post('/file/upload', formData, {
      headers: { 'Content-Type': 'multipart/form-data' }
    })
  }
说明：文件上传要用 FormData 包裹，并设置 multipart/form-data 类型。

十七、富文本编辑器里的特殊语法（RichTextEditor.vue）
----------------------------------------------------------------
1) shallowRef：编辑器实例用 shallowRef 而非 ref
     const editorRef = shallowRef(null)
   原因：wangEditor 实例对象很大，用 ref 会被 Vue 深度追踪（递归
   代理）导致卡顿；shallowRef 只追踪引用本身，不深度响应式，性能更好。

2) defineExpose：把内部方法暴露给父组件
     defineExpose({ getHtml, getText, setHtml, clear, ... })
   父组件（ArticleDialog）便可通过 ref 调用 editor.clear() 等。

3) :deep() 样式穿透：
     :deep(.w-e-toolbar) { background: #f9fafb; }
   原因：scoped 样式默认不影响子组件内部；用 :deep() 可修改
   wangEditor 这类第三方组件的内部 class。

4) v-bind() 在 CSS 中引用 JS 变量：
     .wang-editor { min-height: v-bind(minHeight); }
   作用：把 <script> 里的 minHeight prop 直接用到样式里。

5) onBeforeUnmount：组件销毁前清理
     onBeforeUnmount(() => { editorRef.value?.destroy() })
   作用：防止富文本编辑器内存泄漏。

十八、数据从何处来（总结）
----------------------------------------------------------------
请求链路（见配套图示）：
  页面组件 → api/gutts.js（封装） → utils/request.js（axios 实例+
  拦截器） → Vite 代理 /api → 后端 159.75.169.224:1235
  响应原路返回：后端 → 代理 → 响应拦截器解包 data.data → 组件 ref/reactive

数据来源分类表：
  数据                  来源
  -----------------------------------------------
  token / userInfo      后端 /user/login 返回，存 localStorage；
                        token 用于后续请求头
  分类树 categoryTree    后端接口（经 /api 代理）
  文章列表 articlePage   后端接口（records / total）
  文章详情 / 状态变更     后端接口
  咨询会话 getConsultationPage  后端接口
  文件上传返回 filePath  后端接口，配合 fileBaseUrl 拼成图片地址
  菜单/搜索表单 formItem  前端硬编码在组件里
  标签库 commonTags      前端硬编码
  编辑器工具栏/配色      前端硬编码
  侧边栏折叠状态 isCollapse  Pinia（内存，刷新即重置）
  图标                    main.js 全局注册自 @element-plus/icons-vue
  图片资源                import.meta.url 由 Vite 构建时处理

一句话：所有业务数据来自远程后端 159.75.169.224:1235；前端只负责
发起请求、解包响应、渲染视图，以及维护少量本地状态（token、Pinia）。
